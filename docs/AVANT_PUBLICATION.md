# Vérifications avant de rendre le dépôt public

- [ ] Demander l'accord des autres membres de l'équipe pour publier le code commun, les conceptions et les captures.
- [ ] Définir correctement les contributions personnelles et les crédits de l'équipe (sans s'attribuer le travail des autres).
- [ ] Vérifier d'éventuelles restrictions du cours ou du cégep.
- [ ] Révoquer et régénérer l'ancien jeton d'accès ThingsBoard présent dans les archives d'origine.
- [ ] Faire changer le mot de passe Wi-Fi d'origine par l'administrateur si nécessaire (réseau d'un établissement).
- [ ] Ne publier ni l'ancienne version `main.cpp`, ni les ZIP d'origine, ni `include/secrets.h`.
- [ ] Contrôler avec GitHub Desktop l'onglet **Changes** avant le premier commit, pour être certain qu'aucun secret n'apparaît.
- [ ] Confirmer que les captures n'exposent pas de données privées et que l'équipe accepte leur publication.
- [ ] Vérifier l'origine et les notices de licence du modèle Edge Impulse et des bibliothèques tierces.
- [ ] Tester la compilation et les fonctionnalités sur le matériel si possible, puis noter les résultats mesurés.
- [ ] Ajouter, si disponible, une vidéo réelle du prototype et une photo de l'appareil assemblé.

**Rappel :** la publication est un acte distinct de la préparation locale de l'archive. Commencer par un dépôt **privé** est recommandé.
